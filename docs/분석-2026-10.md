## 1. 무엇을 하는 앱인가

텔포 서버를 쓰는 여행 계획 웹앱입니다.

| 경로 | 화면 |
|---|---|
| `/` | 여행 이름·기간 입력해 새 여행 만들기, 이 브라우저에서 만든 여행 목록(localStorage) |
| `/t/:editToken` | 편집 화면: 일차 탭, 장소 검색·추가, 순서 변경(▲▼·숫자 입력), 구간별 이동수단(자차/도보/대중교통), 메모, 저장, 공유 링크 복사 |
| `/s/:shareToken` | 읽기 전용 공유 화면 |

지도에는 정류지 마커와 순번 뱃지, 구간마다 이동수단 색이 다른 경로선을 그립니다. 같은 도로를 지나는 경로선은 화면상 평행하게 벌려 그리고(`lib/offsetPaths.ts`), 대중교통의 도보 구간만 점선으로 그립니다.

## 2. 구조

```
api/        axios 클라이언트 + trips/places/routes 호출
pages/      HomePage, TripEditPage, TripSharePage
components/ MapView(카카오맵 전담), PlaceSearch, RouteDetail, OrderInput, StopMemo, ShareLinkButton
hooks/      useDayRoutes (구간별 경로 요청 + 클라이언트 캐시)
store/      tripStore (zustand: 여행·정류지 편집 상태)
lib/        날짜/포맷, 카카오 SDK 로더, localStorage, 경로선 평행 이동 계산
types/      서버 응답과 맞춘 타입
```

카카오맵 호출을 `MapView` 하나에 가둬 둔 점, 카카오 REST 키는 서버에만 두고 프론트엔 JS 키만 쓰는 점이 좋습니다.

## 3. 눈에 띄는 문제 (중요도 순)

### 높음
1. **한국 시간에서 날짜가 하루 밀림 (확인함)** — `lib/date.ts`의 `addDays`가 로컬 자정으로 만든 날짜를 `toISOString()`(UTC)으로 잘라서, 한국(UTC+9)에선 하루 전 날짜가 나옵니다. 그래서 출발일이 10.18이면 Day 1 탭이 10.17로 표시됩니다. `HomePage`의 `today()`도 같은 방식이라 오전 9시 전에는 기본 날짜가 어제로 잡힙니다. Node에서 `TZ=Asia/Seoul`로 직접 재현했습니다.
2. **마지막 정류지를 지우면 저장 버튼이 사라짐** — 저장 버튼이 `dayStops.length > 0`일 때만 보이는 패널 안에 있습니다(`TripEditPage.tsx`). 정류지가 하나뿐인 여행에서 그걸 지우면 저장할 방법이 없어 삭제가 서버에 반영되지 않습니다. 패널을 접어도 버튼이 숨습니다.
3. **경로 한 구간이 실패하면 그날 경로가 전부 사라짐** — `useDayRoutes`가 `Promise.all`로 묶고, 하나라도 실패하면 모든 경로선을 비웁니다. 그리고 "계산 중..."이 영원히 남습니다. 대중교통 경로가 없는 구간 하나 때문에 그날 지도 전체가 비게 됩니다.

### 중간
4. **오류 처리 누락** — 편집 화면 로딩(`getTripByEditToken`)에 catch가 없어 잘못된 링크면 "불러오는 중..."에서 멈춥니다. 여행 만들기와 저장 실패도 사용자에게 아무 메시지가 없습니다.
5. **저장 안 한 변경이 쉽게 날아감** — 자동 저장이 없고(서버 주석은 "자동 저장"을 전제), 페이지를 떠날 때 경고(`beforeunload`)도 없습니다.
6. **마커를 매 렌더마다 전부 다시 만듦** — `markers` 배열을 렌더마다 새로 만들어서 `MapView`의 마커 effect가 경로선에 마우스를 올리거나 메모를 칠 때마다 모든 마커와 뱃지를 지우고 다시 그립니다. 정류지가 많으면 버벅일 수 있습니다. `useMemo`로 묶으면 됩니다. 지금 지도 초기화 직후 마커가 그려지는 것도 이 부작용(지도 `idle` 이벤트로 인한 재렌더)에 기대고 있어 깨지기 쉽습니다.
7. **다른 여행으로 이동할 때 이전 여행이 잠깐 보임** — zustand 스토어의 `trip`을 편집·공유 화면이 같이 쓰는데, 새 여행을 불러오기 전에 비우지 않습니다. 선택된 일차(`selectedDay`)도 유지돼 없는 일차가 선택될 수 있습니다.

### 낮음
8. **추천 순서(최적화) 기능이 UI에 연결 안 됨** — `optimizeRoute` API 함수는 있지만 어디서도 호출하지 않습니다.
9. `types/route.ts` 주석이 "KakaoMapProvider는 현재 CAR만 지원"이라고 되어 있는데, 이미 Tmap으로 3종 모두 지원해서 낡은 설명입니다.
10. 테스트가 하나도 없습니다. `lib/date.ts`, `tripStore`, `offsetPaths`는 단위 테스트하기 좋은 대상이고, 1번 버그도 테스트가 있었다면 잡혔을 겁니다.
11. 편집 토큰이 URL과 localStorage에 그대로 있어, 편집 링크(`/t/...`)를 실수로 공유하면 누구나 수정할 수 있습니다. 설계상 의도된 방식이지만 화면에 "이 링크는 편집용"이라는 안내가 있으면 좋겠습니다.
